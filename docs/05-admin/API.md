# API — `/api/v1`

Base URL: `https://api.technology.bingi.com.bd/api/v1` (local `http://localhost:8000/api/v1`).
Auth: `POST /auth/login` → `token`; send `Authorization: Bearer <token>` on every admin call. Tokens last 14 days.

## Errors (every endpoint)
```json
{ "code": "validation_failed", "message": "Some fields need attention.", "fields": { "role": "Write both Bangla and English." } }
```
| HTTP | code | When |
|---|---|---|
| 401 | `unauthenticated` | no/expired token, user disabled |
| 403 | `forbidden` | role cannot do this |
| 404 | `not_found` · `unknown_type` · `not_published` | |
| 409 | `single_exists` · `single_required` · `last_owner` · `duplicate` | conflicts |
| 422 | `validation_failed` · `invalid_login` · `bad_image` | `fields` says which field |
| 429 | `too_many_requests` · `too_many_attempts` | rate limits |

## Admin
Access column = the **default** roles (O owner · E editor · S sales). Access is really checked per module:
`perm:Mxx,view|edit` middleware on each route, and for `/entries/{type}` the type's `module` (types.json).
Roles are rows in the `roles` table and are built in the admin (Users & roles → Roles & permissions).
The module list and the defaults live in `packages/content/modules.json` (generated by `gen-modules.py`).

## Truth guards (422 from the API, whatever the client)
| Type | Rule | Field in `fields` |
|---|---|---|
| module, integration | `status: live` needs `verified_by` + `verified_at` | `verified_by` |
| platform_status | any platform `live` needs the same | `verified_by` |
| module `id: ai` | cannot be `live` | `status` |
| testimonial, client_logo | visible needs `permission_file` | `permission_file` |
| trust_fact | needs `source` | `source` |

## Roles & permissions (M21)

| Method | Path | Access | Notes |
|---|---|---|---|
| GET | `/modules` | signed in | `{ modules: [{ id, label, levels, hint }] }` — the matrix rows |
| GET | `/roles` | M21 view | `{ items: [{ id, key, name{bn,en}, permissions{Mxx: view\|edit}, system, users }] }` |
| POST | `/roles` | M21 edit | `{ name{bn,en}, permissions }` → 201; key made from the English name; `none` levels dropped; level must be allowed by the module (422 `permissions.Mxx`) |
| PATCH | `/roles/{id}` | M21 edit | same body; `owner` (system) → 409 `system_role` |
| DELETE | `/roles/{id}` | M21 edit | system → 409 `system_role`; still has users → 409 `role_in_use` |

`/auth/me` and `/auth/login` return `user.permissions` (`{Mxx: level}`) and `user.role_name`; the admin sidebar,
guards and read-only modes all read it. Dashboard (M02) is always view. Owner always has every module at its top level.
Image upload (`POST /media`) is allowed to any role with Edit on at least one module.
